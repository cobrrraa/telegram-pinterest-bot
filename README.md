# Telegram → Pinterest

Личный Telegram-бот для публикации фотографий в Pinterest. Принимает одиночные фото,
альбомы и изображения, отправленные файлами; предлагает выбрать доску и сохраняет
фотографии в очередь. Для повседневных загрузок использует интеграцию Make,
для больших архивов — отдельные инструменты подготовки CSV для Pinterest.

## Возможности

- Доступ только для одного Telegram ID.
- Выбор доски кнопками; последняя выбранная доска отображается первой.
- Обновление списка досок по команде и кэш на 10 минут.
- Постоянная очередь в JSON с атомарной записью и восстановлением после перезапуска.
- Настраиваемый интервал публикации, по умолчанию 5 минут.
- При распознанном временном отказе повторные попытки через 1, 2, 4 и максимум 6 часов.
- При некоторых ответах остановленного Make очередь ждёт команды `/resume`.
- Сообщение альбома обновляется по мере публикации и содержит ссылки на пины.
- Конвертация изображений и уменьшение крупных файлов.
- Подготовка папки или ZIP к массовой загрузке CSV, до 100 строк на файл.
- Экспорт оставшихся фото из очереди Telegram в CSV.

Подписи Telegram игнорируются. Бот не добавляет заголовок, описание или ссылку к
обычным пинам. В CSV заголовки имеют вид «Фото 1», «Фото 2» и далее.

## Как устроено

```text
Telegram → bot.py → очередь data/queue.json → webhook Make → Pinterest

Папка / ZIP → csv_export.py → JPEG + CSV
                           → файловый сервер → загрузка CSV в Pinterest вручную
```

Собственное developer-приложение Pinterest для сценария Make не требуется:
аккаунт подключается в Make через OAuth. Pinterest по-прежнему использует свой API
и применяет ограничения и антиспам. CSV загружается вручную в интерфейсе Pinterest.

## Требования

- Python 3.10+; проект использовался на Debian 12 с Python 3.11.
- Telegram-бот от [BotFather](https://t.me/BotFather) и числовой ID владельца.
- Аккаунт Pinterest с досками и возможность подключить его в Make.
- Для режима CSV: доступная Pinterest раздача изображений и функция массовой загрузки
  в интерфейсе вашего аккаунта Pinterest.

## Быстрый запуск

```bash
python -m venv .venv
# Linux / macOS:
source .venv/bin/activate
# Windows PowerShell:
# .venv\Scripts\Activate.ps1
pip install -r requirements.txt
cp .env.example .env
```

На Windows вместо `cp` можно использовать `Copy-Item .env.example .env`.
Заполните `.env`, настройте Make по разделу ниже и запустите:

```bash
python bot.py
```

Нужен только исходящий доступ в интернет; Telegram используется через long polling.
Запускайте один экземпляр бота на один токен и файл очереди.

### Переменные окружения

| Переменная | Значение / назначение |
| --- | --- |
| `TELEGRAM_BOT_TOKEN` | Токен BotFather, обязательно |
| `ALLOWED_USER_ID` | Числовой Telegram ID владельца, обязательно |
| `MAKE_WEBHOOK_URL` | Адрес Custom webhook Make, обязательно |
| `MAKE_SECRET` | Длинная случайная строка, также заданная в фильтре Make |
| `PINTEREST_PATH_PREFIX` | `/v5`; оставьте пустым, если модуль Make уже добавляет `/v5` |
| `DATA_DIR` | `data`, каталог очереди и настроек |
| `PIN_INTERVAL_MINUTES` | `5`, интервал между публикациями |
| `BACKOFF_START_MINUTES` | `60`, первая пауза при временном отказе |
| `BACKOFF_MAX_HOURS` | `6`, максимальная пауза |
| `PUBLIC_BASE_URL` | Для экспорта CSV: внешний адрес с префиксом `/p`, например `https://photos.example.com/p` |
| `PUBLIC_DIR` | `public`, каталог изображений файлового сервера и экспорта очереди |
| `FILES_PORT` | `80`, порт файлового сервера |

Секрет можно сгенерировать командой:

```bash
python -c "import secrets; print(secrets.token_urlsafe(32))"
```

`bot.py` и `queue_export.py` читают `.env`. Для `file_server.py` передавайте переменные
через окружение или systemd. `csv_export.py` принимает `--base-url` либо переменную
окружения `PUBLIC_BASE_URL`.

## Настройка Make

Создайте сценарий из четырёх модулей:

1. **Webhooks → Custom webhook.** Его адрес внесите в `MAKE_WEBHOOK_URL`.
   Для определения структуры отправьте боту `/boards`, пока Make ожидает запрос.
   До завершения настройки бот может ответить ошибкой.
2. **Pinterest → Make an API Call.** Подключите Pinterest через OAuth.
   URL — поле `path` первого модуля; Method с включённым Map — только поле `method`;
   Body — поле `body`; заголовок `Content-Type: application/json`.
3. **JSON → Transform to JSON.** Object — `Body` модуля Pinterest.
4. **Webhooks → Webhook response.** Status — `Status code` Pinterest,
   Body — `JSON string` предыдущего модуля, заголовок `Content-Type: application/json`.

Между первым и вторым модулями поставьте фильтр: поле `secret` равно вашему `MAKE_SECRET`.
Сохраните сценарий и включите обработку сразу при поступлении данных.

Пример структуры запроса (значения демонстрационные):

```json
{
  "secret": "your-shared-secret",
  "method": "GET",
  "path": "/v5/boards?page_size=100",
  "body": ""
}
```

Если Pinterest сообщает `Missing: ['boards:read']` или не хватает права создания пинов,
добавьте временно штатные модули **List Boards** / **Create a Pin**, выберите подключение
и повторно разрешите запрошенные права. После настройки удалите временные модули.

### Передача ошибок Pinterest

У модуля Pinterest добавьте **Add error handler → Webhooks → Webhook response**:
Status `422`, Body — поле **Error → Message** Pinterest, обычный текст без JSON-заголовка.
Это позволяет боту отличать слишком маленькую картинку от временного ограничения.
Без обработчика Make обычно возвращает общий `Scenario failed to complete`, и бот
считает такую ошибку временной. Проверьте ветку ошибки в своём сценарии перед использованием.

Успешный запрос в описанном сценарии использует примерно четыре кредита Make;
запросы списка досок и неудачные попытки тоже могут расходовать кредиты.
Точные тарифы и остаток смотрите в аккаунте Make. Интервал не гарантирует отсутствие антиспама.

## Команды Telegram

| Команда | Действие |
| --- | --- |
| `/start`, `/help` | Подсказка |
| `/boards` | Принудительно обновить список досок |
| `/queue` | Показать размер очереди и время следующей попытки |
| `/resume` | Продолжить очередь после ручной паузы из-за ответа Make |
| `/clearqueue` | Удалить ожидающие задания из очереди |

Очередь сохраняется после выбора доски. Невыбранные фото и собираемые альбомы пока
находятся в памяти и могут потребовать повторной отправки после перезапуска.

## Docker

```bash
docker compose up -d --build
docker compose logs -f
```

Compose сохраняет `data` на хосте. Это запуск Telegram-бота; файловый сервер для CSV
разворачивается отдельно.

## Debian / Ubuntu и systemd

Скопируйте исходники в `/opt/pinterest-bot`, затем:

```bash
sudo useradd --system --home-dir /opt/pinterest-bot --shell /usr/sbin/nologin pinbot
sudo chown -R pinbot:pinbot /opt/pinterest-bot
cd /opt/pinterest-bot
sudo -u pinbot python3 -m venv .venv
sudo -u pinbot .venv/bin/pip install -r requirements.txt
sudo -u pinbot cp .env.example .env
# Заполните .env перед запуском.
sudo chmod 600 .env
sudo cp deploy/pinterest-bot.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now pinterest-bot
sudo journalctl -u pinterest-bot -f
```

В шаблоне службы установлен лимит памяти 256 МБ и CPU 50%. Для другого пути или
пользователя измените service-файл. После обновления исходников перезапустите службу.
Перед обслуживанием сохраняйте резервную копию `data/`.

## Большие архивы через CSV

CSV-режим проверялся на реальной загрузке архива. Он не расходует кредиты Make,
но принятие CSV и получение JPEG сервером Pinterest ещё не подтверждают создание всех пинов.
Окончательный результат проверяется на доске и по отчётам Pinterest.

### 1. Подготовить изображения

```bash
python csv_export.py ./photos --board "Название доски" \
  --base-url https://photos.example.com/p --out export --start 1
```

Вместо папки можно передать ZIP. Скрипт исправляет поворот EXIF, конвертирует в JPEG,
уменьшает до 4000 px, исключает точные файловые дубли и изображения с короткой стороной
меньше 200 px. Последнее — локальный фильтр, а не гарантия принятия Pinterest.
Для HEIC дополнительно установите `pip install pillow-heif`.

Результат: CSV по 100 пинов и каталог JPEG со случайными именами. Для следующего
архива используйте новый `--out`, чтобы не перезаписать прошлые CSV. `--start` задаёт
начало нумерации; названия досок должны совпадать с Pinterest.

### 2. Раздать фото

Скопируйте созданный каталог JPEG внутрь `/opt/pinterest-bot/public/` своего сервера.
Внешний адрес должен соответствовать `--base-url`. Приложение раздаёт `/p/` без листинга.

```bash
sudo cp deploy/pinterest-files.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl start pinterest-files
sudo journalctl -u pinterest-files -f
```

Служба использует порт 80 и capability `CAP_NET_BIND_SERVICE`; проверьте, что порт свободен.
Для HTTPS настройте обратный прокси и подходящий `FILES_PORT`.
Ссылки публичные: любой получивший ссылку сможет открыть изображение. Случайные имена
не заменяют авторизацию. Личные фото, CSV со ссылками и исходные архивы не входят в Git.

### 3. Загрузить CSV

В настольном интерфейсе Pinterest выберите массовое создание пинов и загрузите CSV.
Оставьте изображения доступными до завершения обработки и проверьте появление пинов.
Отчёты Pinterest помогут найти отклонённые строки; повторная загрузка всего файла может
создать дубли уже опубликованных пинов.

### 4. Выгрузить очередь в CSV при необходимости

Остановите бот, сделайте резервную копию `data/` и выполните на сервере:

```bash
sudo systemctl stop pinterest-bot
cd /opt/pinterest-bot
sudo -u pinbot .venv/bin/python queue_export.py --start 101 \
  --base-url https://photos.example.com/p
sudo systemctl start pinterest-bot
```

Файлы появятся в `public/csv/`. При успешном скачивании всей очереди скрипт очищает её
и обновляет сообщения Telegram. Если часть файлов скачать не удалось, очередь сохраняется;
не загружайте частичный CSV вместе с продолжающейся очередью, чтобы избежать дублей.
Сохраните CSV локально и уберите их из публичного каталога после скачивания.

После подтверждения публикаций остановите файловую службу и удалите только завершённые
каталоги изображений. Для разовой загрузки включать автозапуск раздачи не требуется.

## Ограничения и диагностика

Проверки без подключения к Telegram и Make:

```bash
python -m unittest discover -s tests -v
```

Тесты проверяют восстановление очереди, CSV с заданным адресом сервера,
исключение файловых дублей и ответы Make.

- `429 / hit a block`: очередь ждёт; правила и длительность ограничений задаёт Pinterest.
- `image is too small`: используйте оригинал большего размера.
- `Accepted` вместо JSON: проверьте включённый сценарий Make и его Webhook response.
  При неопределённом результате запроса пин мог появиться позже; перед повтором проверьте доску.
- `/v5/v5/...`: исправьте `PINTEREST_PATH_PREFIX` в соответствии с подсказкой Make.
- Бот молчит: проверьте `ALLOWED_USER_ID` и логи службы.
- Повреждённый JSON очереди текущая реализация считает пустым: сохраняйте резервные копии.
- Доставка не гарантирует exactly-once: прерывание между созданием пина и сохранением
  результата или сетевой таймаут может потребовать ручной проверки дублей.
- Для экспорта CSV сверяйте актуальные требования интерфейса Pinterest и его отчёты.

В репозитории находятся только исходники и шаблоны: токены, webhook, личные фото,
рабочая очередь и адрес частного сервера исключены.
